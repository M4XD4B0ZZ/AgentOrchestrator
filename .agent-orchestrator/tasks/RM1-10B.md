## 1. Goal

The versioned supervisor in `ops/zera-supervisor/` runs from whatever folder it is deployed to,
keeps its state in a folder of its own, and no output of it ever names the notification channel.
With no parameter, every path resolves exactly as today: the scheduled task's action path and
working directory (`C:\Users\Max\AO-runs`) need no change, and a rollback is a copy of the old
files.

## 2. Invariants (each one is tested)

1. **Two folders.** `$SourceDir` is the folder of the running script (`$PSScriptRoot`). The five
   helper scripts (`ao-classify.mjs`, `zera-delivery-gate.mjs`, `zera-quota-grant.mjs`,
   `zera-operator-repair-grant.mjs`, `zera-writer-death-grant.mjs`) are joined from it.
   `$StateDir` is the parameter `-StateDir`, else the environment variable `ZERA_STATE_DIR`, else
   `C:\Users\Max\AO-runs`. The status file, the retry ledger, the lock, the last-notify stamp and
   `transcripts/` are joined from it. No state file comes from `$SourceDir`, no script from
   `$StateDir`.
2. **Machine paths are parameters.** `-AoRoot` and `-RepoRoot`, with today's values as defaults.
   The supervisor passes `AO_ROOT` and `--budget <ledger>` explicitly on every prover call, so no
   prover falls back to its built-in path when the supervisor calls it. The provers do not change.
3. **Rollback compatible.** One pure function, `Resolve-ZeraPaths`, returns the whole path table.
   With source and state both `C:\Users\Max\AO-runs` and no other parameter, the table equals
   today's paths exactly. `-DryRun` and `--dry-run` both still work.
4. **The channel is never printed.** No line on the console, in the transcript, in the status file
   or in a caught exception message contains the ntfy topic or the endpoint-plus-topic URL. The
   dry-run line names the title only (`DRY-RUN: would notify -- <title>`). A failed notify prints a
   closed message with no URL and no exception text.
5. **State is never moved.** Nothing creates, moves, resets or copies the retry ledger outside
   `$StateDir`; its path under the default and its shape stay as they are.
6. **Byte rules stay.** UTF-8 BOM on every `.ps1`, LF only. `tests/ops-zera-supervisor.test.ts`
   keeps its existing cases.
7. **Grant wiring unchanged.** Each grant flag is still reachable only through the lane that proved
   it, and the supervisor still authors exactly one commit. `zera-wiring-test.ps1` is updated for
   `$SourceDir` and keeps every existing check.

## 3. Tests (red first)

In `tests/ops-zera-supervisor.test.ts`, on Windows, through `powershell.exe`. No network, no real AO
or HealthApp. The supervisor script is never run or dot-sourced: a case loads single functions from
its syntax tree (as the wiring test already parses it) into a fresh PowerShell.

1. `Resolve-ZeraPaths`: the default table equals today's paths (pinned value by value); with two
   distinct folders every helper is under the first and every state file under the second;
   `ZERA_STATE_DIR` wins over the default, and `-StateDir` wins over both.
2. Redaction: `Notify` and `Test-NotifyIsNew`, with `USERPROFILE` pointing at a temporary folder
   whose `.agent-orchestrator\notify.yaml` holds a sentinel topic and with the state in a temporary
   folder. Once in dry run, once with an endpoint that refuses (`http://127.0.0.1:9`): the sentinel
   and the URL appear in no output stream.
3. Static: `zera-supervisor.ps1` contains `C:\Users\Max\AO-runs` exactly once (the default of
   `$StateDir`), and no helper path is a literal.
4. The updated wiring test passes (`WIRING_VERDICT = ALL_PASS`), and a copy whose prover path is
   joined from `$StateDir` fails it.

Each case must fail on a copy with the part it pins removed.

## 4. The grant lab

`zera-grant-lab.mjs` takes `--ao-root`, `--source-dir`, `--lab` and `--budget`, and keeps no
built-in machine path. It still runs only by hand, against a deployed AO runtime, and never against
the state in `C:\Users\Max\AO-runs`. It is not added to CI here (the ADR leaves that open).
