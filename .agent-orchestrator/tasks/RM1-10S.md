## 0. Authority

`ROADMAP.md`, RM1-10 (decision D6 = A, 2026-10-19). Operator decision of 2026-10-19 on RM1-10B:
AO implements it, and the scope is widened in a separate, secured change. This file is the record
of that change. It is the prerequisite of RM1-10B (`dependsOn`), and the lock that keeps RM1-10B
from starting: AO refuses a task whose dependencies are not `DONE` (`src/plan/select-task.ts`,
`src/run/start-task.ts`).

## 1. This task is not for an agent

A person delivers it, in its own pull request, and that pull request sets this file to `DONE`. An AO
writer cannot do it: its only change is in `.agent-orchestrator/repo-profile.yaml`, which is outside
`scope.allowedPaths`, so the scope gate refuses the pass. If an agent is started on it anyway:
change nothing, and STOP.

## 2. The change

In `.agent-orchestrator/repo-profile.yaml`, `scope.allowedPaths` gets exactly these four files, each
as its own entry, and nothing else:

- `ops/zera-supervisor/zera-supervisor.ps1`
- `ops/zera-supervisor/zera-wiring-test.ps1`
- `ops/zera-supervisor/zera-grant-lab.mjs`
- `ops/zera-supervisor/README.md`

Not `ops/`, and not `ops/zera-supervisor`: a directory entry would let a writer add files there and
change the five provers and `zera-register-task.ps1`, which RM1-10B must not change. An entry names
a path and everything under it (`src/scope/scope-policy.ts`), so a file entry names that one file.
`protectedPaths`, the verification phases and every other key stay as they are.

## 3. Effect, measured before the change

- AO reads the scope of a task from the profile at the base commit of that task
  (`src/scope/pinned-scope.ts`). A task that already has a state keeps the scope it started with. On
  2026-10-19 that is 12 of the 13 `OPEN` tasks of this repository. `REVIEW-INSTRUMENT-001` has no
  state yet, and it gets the four files if it starts after the change.
- The entries apply to the whole repository: AO has no scope per task. Every task that starts while
  they stand may change the four files.

## 4. Way back

After RM1-10B is delivered, a later change can remove the four entries (operator decision). The
removal changes no task that has already started, for the reason in section 3.
